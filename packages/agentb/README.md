# agentb — A2A downstream agent ("Agent B")

The **dual-natured** agent in osage's A2A identity-chaining demo. Agent B is
simultaneously:

- an **a2a-server** (resource): it exposes the [A2A protocol](https://a2a-protocol.org/)
  (an AgentCard + a JSON-RPC `message/send` endpoint) and validates the inbound
  access token agent0 presents; and
- a **principal**: having received a call carrying the original user's identity,
  it performs its **own** token exchange — authenticating as itself — to obtain a
  user-scoped access token for **todo0**, then acts on todo0 on the user's behalf.

This is the **second hop** of identity chaining. The original user's `sub` is
preserved at every step; the audience narrows from Agent B → todo0.

```
agent0 --A2A (Bearer AT, aud=AgentB)--> Agent B
   Agent B: verify inbound token (issuer=A2A AS, aud=resourceUrl, scope=agent.invoke)
   Agent B: AT --(Org AS, token-exchange, resource=todo0)--> id-jag
            id-jag --(todo0 MCP AS, jwt-bearer)--> AT (aud=todo0)
   Agent B --MCP (Bearer AT)--> todo0   (sub = original user throughout)
```

## Files

- `src/index.ts` — entry point; validates env, starts the server.
- `src/config.ts` — env loading/validation (`.env.agentb`).
- `src/server.ts` — A2A protocol server: AgentCard + JSON-RPC `message/send`.
- `src/auth/inbound.ts` — inbound token validation (`@okta/jwt-verifier`).
- `src/auth/token-exchange.ts` — the outbound second hop (access_token → id-jag → todo0 AT).
- `src/todo-client.ts` — MCP client to todo0.
- `src/handler.ts` — interprets the A2A task and acts on todo0.

## Run

Configure `packages/agentb/.env.agentb` (auto-generated by `pnpm run bootstrap:okta`
when A2A is enabled; otherwise copy `.env.agentb.example`). Then:

```sh
pnpm --filter agentb run build
pnpm --filter agentb run start   # listens on AGENTB_PORT (default 5005)
```

> **Note on the A2A transport.** This package implements the A2A protocol surface
> directly (AgentCard at `/.well-known/agent-card.json` + JSON-RPC `message/send`)
> with no A2A SDK dependency, matching osage's low-dependency style. It can be
> swapped for `@a2a-js/sdk` without changing the identity-chaining logic.
